LESSON 1

Callbacks: a function you hand over

About 45 minCode-along step A1

By the end you can say what a callback is, tell a now callback from a later callback, and pass a function without accidentally calling it.

Watch
Learn JavaScript CALLBACKS in 7 minutes!
Bro Code · watch this first Main Asynchronous JavaScript Tutorial #4: Callback Functions
Net Ninja · uses an older way to request data (XMLHttpRequest); focus on the callback idea Optional
Read · 1. Functions are values

In JavaScript a function is a value, like a number or a string. You can store it in a variable or pass it to another function. The name without parentheses is the function itself. The name with parentheses runs it.

function sayHi() {
  console.log("Hi!");
}

const greet = sayHi;   // no () → we copied the function, nothing runs
greet();               // () → now it runs: Hi!
Read · 2. A callback is a function you pass in

A callback is a function you give to another function, so that function can call it for you. You decide what should happen; the other function decides when.

function doTwice(action) {
  action();   // the function we were given is called here…
  action();   // …and here
}

doTwice(sayHi);   // Hi!  Hi!   (pass sayHi, don't call it)

You have used callbacks since Week 11 without the name. They come in two kinds:

KindExampleWhen it runs
Now (synchronous)[1, 2, 3].forEach((n) => console.log(n))Right away, before the next line
Later (asynchronous)setTimeout(sayHi, 2000)After 2 seconds, when the stack is empty
Later (asynchronous)btn.addEventListener("click", sayHi)Whenever the user clicks, maybe never
Try it
Now vs. later callbacks
console.log("A");
[1, 2].forEach((n) => console.log(n));        // now
setTimeout(() => console.log("B"), 0);       // later
console.log("C");
  1. Click Run. The number on the left is the time since you clicked.

The forEach callback runs immediately, inside the line that calls it. The setTimeout callback goes to the browser and comes back only after every other line has finished.

Read · 3. The #1 callback mistake: sayHi vs sayHi()

Adding () calls the function right now and passes along whatever it returns (here, undefined).

setTimeout(sayHi, 2000);      // ✓ pass the function: "Hi!" after 2 s
setTimeout(sayHi(), 2000);    // ✗ runs sayHi NOW, then setTimeout gets undefined

btn.addEventListener("click", sayHi);     // ✓ runs on every click
btn.addEventListener("click", sayHi());   // ✗ runs once on page load, never on click
See the difference
  1. Click Run. Both versions start at the same moment.

Need to pass arguments? Wrap the call in an arrow function, so it is what gets passed: setTimeout(() => greetUser("Ana"), 2000).

Read · 4. Callbacks that receive data

Often the function that calls your callback hands it a value. You choose the parameter name. These three lines all pass the same kind of callback:

brewWithCallback("Pili Latte", function (cup) { console.log(cup); });
brewWithCallback("Pili Latte", (cup) => { console.log(cup); });
brewWithCallback("Pili Latte", (cup) => console.log(cup));

// inside brewWithCallback, after 2 seconds:  done(drink + " ☕");
// whatever is passed to done(...) arrives as cup
Predict: what does this print, and in what order? 
function later(fn) {
  setTimeout(fn, 1000);
}

console.log("start");
later(() => console.log("one second later"));
later(console.log("oops"));
console.log("end");

Answer: start, oops, end, then one second later. The third line has (), so console.log("oops") runs immediately and later receives undefined. Nothing else happens a second later for that call.

LESSON 2

Callback hell: steps inside steps

About 30 minCode-along step A2

By the end you can explain why steps that must happen in order lead to nested callbacks, and read an error-first callback.

Watch
What is JavaScript CALLBACK HELL?
Bro Code Main
Read · Order means nesting

A coffee order has three steps: take the order (1 s), brew (2 s), serve (1 s). Brewing can only start when the order is taken, so the "brew" call has to go inside the "take order" callback. Serving goes inside the brewing callback. Each step adds a level.

Each step can also fail. The usual convention for callbacks is error-first: the callback's first parameter is an error (or null when everything worked), and the second is the result.

takeOrderCb(drink, (error, confirmed) => {
  if (error) { show(error); return; }          // check #1
  brewCb(confirmed, (error, cup) => {
    if (error) { show(error); return; }        // check #2
    serveCb(cup, (error) => {
      if (error) { show(error); return; }      // check #3
      show("Order complete!");
    });
  });
});
Run the nested order
  1. Times are shortened. Try Ube Latte: it's sold out.

Why it hurts: the code grows to the right with every step; every level needs its own error check; adding or reordering a step means re-nesting everything.

Read · Before Promises: name your functions

One way to flatten the pyramid is to give each step a name. It reads better, but you still pass callbacks around and check errors at every step. Promises (Lesson 3) solve both problems.

function start(drink) { takeOrderCb(drink, afterOrder); }
function afterOrder(error, d) { if (error) return show(error); brewCb(d, afterBrew); }
function afterBrew(error, cup) { if (error) return show(error); serveCb(cup, done); }
function done() { show("Order complete!"); }

LESSON 3

Promises: an order number for a value

About 40 minCode-along steps A3–A4

By the end you can name the three states of a Promise, make one with new Promise, and chain steps with .then(), .catch() and .finally().

Watch
What are JavaScript PROMISES?
Bro Code Main JavaScript Promises In 10 Minutes
Web Dev Simplified · a second explanation, good if the first didn't click Optional
Read · Three states

When you pay at a café you don't get coffee, you get an order number. A Promise is that number: an object you get right away that stands for a value that isn't ready yet.

StateMeaningHow it gets there
pendingStill workingEvery Promise starts here
fulfilledDone, here's the valueresolve(value)
rejectedFailed, here's the errorreject(error)

Once a Promise is fulfilled or rejected (together called settled), it never changes again.

Read · Make one, then use it
function takeOrder(drink) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (SOLD_OUT.includes(drink)) {
        reject(new Error(`Sorry, ${drink} is sold out`));
      } else {
        resolve(drink);
      }
    }, 1000);
  });
}

takeOrder("Pili Latte")
  .then((drink) => brew(drink))      // gets the value from resolve
  .then((cup) => serve(cup))
  .catch((error) => show(error.message))   // ANY step that rejects lands here
  .finally(() => setBusy(false));          // runs either way

Compare this with Lesson 2: the same three steps, flat, with one error handler.

Run the Promise chain
  1. Times are shortened. Try both drinks.

The return rule. Each .then must return the next Promise, or the chain stops waiting. An arrow function without braces returns automatically. With braces you must write return:

.then((drink) => brew(drink))              // ✓ returns automatically
.then((drink) => { return brew(drink); })  // ✓
.then((drink) => { brew(drink); })         // ✗ returns undefined: the next step runs too early
Predict: what is logged right away, and what after 1 second? 
const p = takeOrder("Pili Latte");
console.log(p);
p.then((drink) => console.log("Got:", drink));
console.log("waiting…");

Answer: right away, Promise {<pending>}, then waiting…. After 1 second, Got: Pili Latte. The Promise exists immediately; its value doesn't.

LESSON 4

async / await: Promises that read like normal code

About 35 minCode-along steps A5–A6

By the end you can rewrite a .then() chain with async/await and try/catch, and run independent jobs together with Promise.all.

Watch
JavaScript ASYNC/AWAIT is easy!
Bro Code Main Asynchronous JavaScript Tutorial #10: Async & Await
Net Ninja Optional
Read · Same order, two ways
// with .then()
takeOrder(drink)
  .then((d) => brew(d))
  .then((cup) => serve(cup))
  .catch((e) => show(e.message))
  .finally(() => setBusy(false));

// with async / await
async function placeOrder(drink) {
  try {
    const d = await takeOrder(drink);   // wait, then give me the value
    const cup = await brew(d);
    await serve(cup);
  } catch (e) {
    show(e.message);                     // a rejected Promise lands here
  } finally {
    setBusy(false);
  }
}
  • await waits for a Promise and gives you its value.
  • await only works inside a function marked async.
  • await pauses that function, not the page. Other code and clicks keep running.
await pauses the function, not the page
placeOrder("Iced Mocha");
console.log("placeOrder() was called; the page is still free");
  1. Watch where the second line appears.
Read · Promise.all: three baristas

If jobs don't depend on each other, start them all and wait for all of them. Promise.all takes as long as the slowest job, not the total.

for (const d of orders) { await brew(d); }                    // one at a time
const cups = await Promise.all(orders.map((d) => brew(d)));   // all at once
One at a time vs. Promise.all
  1. Each brew takes 1 s here (2 s in the code-along).

fetch(): getting real data

About 45 minCode-along steps B1–B5

By the end you can load a JSON file with fetch, check response.ok, show loading and error messages, and call a public API.

Watch
How to FETCH data from an API using JavaScript
Bro Code Main Learn Fetch API In 6 Minutes
Web Dev Simplified Optional Asynchronous JavaScript Tutorial #9: The Fetch API
Net Ninja Optional
Read · From a URL to cards on the page

fetch(url) returns a Promise for a Response. Reading its body with .json() returns another Promise, for the data. So there are two awaits.

async function loadEvents() {
  statusText.textContent = "Loading events…";
  try {
    const response = await fetch("data/events.json");
    if (!response.ok) {                                   // 404, 500, …
      throw new Error("HTTP " + response.status);
    }
    const events = await response.json();               // a normal array
    renderEvents(events);                                 // Week 11 DOM skills
    statusText.textContent = events.length + " events loaded.";
  } catch (error) {
    statusText.textContent = "⚠ " + error.message;
  }
}
You seeIt meansFix
HTTP 404Wrong path or file nameCheck spelling and folders. fetch does not reject on 404, so check response.ok
blocked by CORS policyPage opened as file://Open it with Live Server
Unexpected token … not valid JSONThe file isn't valid JSON, or you got an HTML error pageDouble quotes on keys, no trailing comma; check the URL
Failed to fetchNo internet, or the server is downYour catch should show a friendly message
Predict: the file name is wrong. Which message shows, and why? 
fetch("data/event.json")          // missing the "s"
  .then((res) => res.json())
  .then((data) => renderEvents(data))
  .catch((err) => show("Error: " + err.message));

Answer: fetch itself succeeds (the server answered, with a 404), so the first .then runs. res.json() then fails because the 404 page is HTML, not JSON, so .catch shows a confusing "Unexpected token" message. Checking res.ok first turns it into a clear "HTTP 404".
